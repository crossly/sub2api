## 1. OpenAI Over-Limit / 429 Routing

### Intent

When OpenAI over-limit mode is enabled, a rate-limited OpenAI account must remain eligible enough to be tried according to normal priority ordering. If it returns `429` or compatible upstream pressure errors, the request should fall through to later eligible accounts. This preserves the intended behavior:

- Lower numeric priority still wins.
- Priorities are not hard-coded.
- A `429` account can be the first attempted account.
- The final successful account keeps normal usage attribution.
- Failed `429` attempts do not rewrite `UsageAttributionAccount`.
- `prompt_cache_key` is preserved on over-limit OAuth paths to keep cache identity stable.

### Primary Files

- `backend/internal/service/openai_over_limit_strategy.go`
- `backend/internal/service/openai_account_scheduler.go`
- `backend/internal/service/openai_gateway_service.go`
- `backend/internal/service/openai_account_runtime_block_fastpath.go`
- `backend/internal/service/openai_gateway_messages.go`
- `backend/internal/service/openai_codex_transform.go`
- `backend/internal/service/openai_ws_forwarder.go`

### Strategy Layer Responsibilities

`openai_over_limit_strategy.go` owns the local policy and should stay the main merge boundary:

- Read and cache `openai_over_limit_mode_enabled`.
- Read, normalize, and cache `openai_over_limit_cooldown_seconds`.
- Normalize enabled cooldown values so empty or `< 10` becomes `10`.
- Track short cooldown by `account + model`.
- Decide whether a rate-limited account is still selectable under over-limit mode.
- Broaden candidate lookup beyond upstream schedulable-only filtering.
- Decide whether sticky session should yield to higher-priority over-limit candidates.
- Decide whether `previous_response_id` should be ignored during over-limit routing.
- Mark short cooldown after upstream `429` or `529`.

### Hook Points To Recheck On Every Upstream Merge

- Candidate lookup: `listSchedulableAccounts` and `listOpenAIAccountsForOverLimitMode`.
- Eligibility: `isOpenAIAccountEligibleForRequest` and `isOpenAIAccountSelectableForRequest`.
- Scheduler: `selectAccountWithScheduler`, `selectBySessionHash`, and `selectByLoadBalance`.
- Sticky behavior: `tryStickySessionHit` and scheduler session-hash selection.
- Previous response behavior: `shouldIgnorePreviousResponseForOpenAIOverLimit`.
- Cache identity: `shouldPreserveLegacyCacheIdentityForOpenAIOverLimit`.
- Upstream error handling: calls to `maybeMarkOpenAIOverLimitCooldown`.
- Runtime block fast path: `openai_account_runtime_block_fastpath.go`.

### Merge Rules

- Keep over-limit behavior isolated in the strategy layer whenever possible.
- Do not hard-code priority values such as `1` or `11`.
- Do not change usage attribution to the failed `429` account.
- Do not disable upstream scheduler features globally; only bypass sticky/load-balance behavior when over-limit policy requires it.
- If upstream changes official `429` handling, first identify whether it is generic account health logic or over-limit routing policy. Only the latter belongs in this local layer.

## 3. Docker, Release, And Coolify

### Intent

Avoid rebuilding the full image on the Coolify host and reduce Docker build pressure when local builds are needed.

### Files

- `Dockerfile`
- `docker-compose.coolify.yml`
- `deploy/docker-entrypoint.sh`
- `frontend/package.json`
- `backend/cmd/server/VERSION`

### Changes

- `Dockerfile` pins `PNPM_VERSION=10.33.0`.
- Frontend dependency install uses a BuildKit pnpm store cache.
- Frontend Docker build runs `pnpm run build:docker`.
- Go module download and Go build use BuildKit cache mounts.
- Coolify compose uses `ghcr.io/crossly/sub2api:latest` with `pull_policy: always`.
- Runtime entrypoint prints image ref and binary version when the container starts.

### Merge Rules

- If upstream rewrites Docker stages, reapply cache mounts and `PNPM_VERSION` together.
- Keep Coolify compose image-based deployment separate from over-limit patches.
- If release tags change, verify GHCR image publishing before changing Coolify image references.
